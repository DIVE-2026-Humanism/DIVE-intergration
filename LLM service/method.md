## 0. 목적과 설계 원칙

KCB 신용 마이크로데이터 10만 행을 입력받아 부산 청년 1인가구를 **6개 경제 계층 유형**으로 분류하고, 유형별 프로파일·검증 리포트·**8문항 축소 분류기**를 산출한다.

### 설계 원칙 5가지

1. **KCB 데이터는 서비스 입력이 아니라 라벨 생성기다.** 실제 사용자는 42개 금융변수를 제공할 수 없다. 배치로 정밀 라벨을 만들고, 사용자가 답할 수 있는 8문항으로 그 라벨을 재현하는 축소 모델을 학습한다.
2. **모든 임계값은 분위수 기준이다.** 합성데이터의 스케일이 실제와 다를 수 있으므로 절대값 임계값(예: DSR 40%)을 쓰지 않는다.
3. **설명 가능성이 성능보다 우선한다.** 최종 수요자는 부산시 공무원이다. 부스팅 계열 블랙박스를 쓰지 않고, 판정 근거를 규칙으로 출력할 수 있는 모델만 사용한다.
4. **PCA·GMM은 "쓴다"가 아니라 "쓸 수 있는지 먼저 검증한다".** 예비 검사에서 상관 구조와 군집 구조가 모두 약하게 나왔다(부록 A). 진단 후 분기 규칙에 따라 결정한다.
5. **학습은 정당한 곳에만 넣는다.** 억지 모델을 만들지 않고, 실제 관측값을 타깃으로 하는 과제 위주로 구성한다(§9, §11).

## 4. STEP 0 — 논리 정합성 검증 + 열 제거 적용 (`consistency.py`)

합성데이터는 컬럼이 독립 생성되어 논리 제약이 걸리지 않은 경우가 많다. 검증 결과를 기록한 뒤 **확정된 열 제거를 즉시 적용하고 다음 단계로 진행한다.**

### 4.1 검사 실행

검사 26종, 심각도 3단계(FATAL / MAJOR / MINOR).

| 그룹 | 내용 |
|---|---|
| A. 자산 | 순자산 > 총자산, 자산 있으나 매매가 0 |
| B. 대출 | 건수·약정·잔액·상환액 정합성, 잔액 > 약정 |
| C. 카드 | 일시불+할부 vs 총 소비액, 현금서비스 vs 신용카드 |
| D. 연체 | 건수·금액·일수 3자 정합성, 연체금액 > 대출잔액 |
| E. 소득 | 증빙 vs 추정 괴리, 월소득×12 vs 연소득, 연소득 0 |
| F. Thin Filer | Thin Filer인데 금융활동 존재 |
| G. 고용 | 직장이력 0인데 이직 증감액 존재 |
| H. 주거 | 전세가 > 매매가, 자가인데 자산 0 |

## 6. STEP 2 — ★ 데이터 분할 (`split.py`)

**모든 학습의 전제.** 이 지점 이후 계산되는 모든 통계량은 train에서만 산출한다.

```
train 70%  /  valid 15%  /  test 15%
stratify = 연령대 × 성별
```

### 누수 방지 규칙 (가장 틀리기 쉬운 지점)

train에서만 계산하고, valid/test와 실서비스에는 **저장된 값을 적용**한다.

- 분위수 임계값 (축 스코어, 세그먼트 컷)
- 구간(binning) 경계
- 지역별 중앙값 (전세가 등)
- 모든 모델 파라미터

> 전체 데이터로 분위수를 뽑아 라벨을 만든 뒤 분할하면, test에 분포 정보가 누수되어 축소 분류기 정확도가 부풀려진다. 산출된 모든 기준값은 `outputs/fitted_params.json`에 저장할 것.

## 7. STEP 3 — [학습 ①] 전세가 결측 대체 (`impute.py`)

**목적: 주거 축 복원**

문제: `2년내 현거주지평균전세거래가`가 65.7% 결측(관측 34,623건). 주거 부담을 잴 유일한 직접 지표인데 그대로는 축에 못 쓴다.

| 항목 | 내용 |
|---|---|
| 입력 | 거주지 시군구 / 연령대 / 추정 연소득 / 아파트여부 / 현 거주지의 매매가 |
| 타깃 | `2년내 현거주지평균전세거래가` (관측 34%) |
| 모델 | `RandomForestRegressor` |
| 베이스라인 | 거주지 시군구별 중앙값 대입 |
| 검증 | 관측분 홀드아웃 → MAE, R² |

**판정**: 모델 MAE < 베이스라인 MAE 이면 모델 사용, 아니면 구·군 중앙값 대입.

**적용**: 결측 66%에 예측값 대입 + `jeonse_imputed` 플래그 생성.

산출: `imputer_jeonse.pkl`

> 부산 16개 구·군이면 구당 평균 약 2,100건이라 중앙값 베이스라인도 충분히 안정적이다. 모델이 이를 못 이기면 미련 없이 중앙값을 쓸 것.

## 9. STEP 5 — [학습 ②] 신용평점 잔차 모델 (`residual.py`) ★ 핵심

**발상: "조건 대비 설명되지 않는 저평점"을 정량 정의한다.**

| 항목 | 내용 |
|---|---|
| 입력 | 소득·대출·소비·고용 파생변수 (**신용평점 및 그 파생물 제외**) |
| 타깃 | `신용평점` ← **실제 관측값이므로 순환논리 없음** |
| 모델 | `RandomForestRegressor` 또는 `Ridge` (부스팅 금지) |
| 검증 | test RMSE, R² |

```
credit_score_residual = 실제 신용평점 − 예측 신용평점
```

| 잔차 | 해석 | 활용 |
|---|---|---|
| 크게 음수 | 조건은 멀쩡한데 점수가 낮음 | **T3 사각지대 후보** |
| ≈ 0 | 설명되는 점수 | — |
| 크게 양수 | 조건 대비 점수가 높음 | T1 후보 |

**활용**: 잔차를 파생변수로 추가해 STEP 6 축 구성에 투입한다. "왜 이 청년은 조건 대비 점수가 낮은가"가 곧 정책 개입 지점이 된다.

**주의**: `score_floor`(신용평점 150) 행은 하한 절단이므로 잔차가 인위적으로 음수가 된다. 학습에서 제외하거나 별도 표기할 것.

산출: `score_residual_model.pkl`

## 10. STEP 6 — 축 스코어 (`scores.py`)

### 10.1 축 구성

**X축 `financial_stress_score` (재무 스트레스, 높을수록 나쁨)**

```
dsr                (+)
delinq_severity    (+)
total_delinq_cnt   (+)
cash_advance_flag  (+)
consumption_ratio  (+)
신용평점            (−)  방향 반전
```

**Y축 `employment_instability_score` (고용 불안정, 높을수록 나쁨)**

```
job_turnover            (+)
income_trajectory       (−)  방향 반전
has_verified_income     (−)  방향 반전
thin_filer              (+)  ← 보강
credit_score_residual   (−)  ← 보강 (STEP 5 산출)
```

> ⚠️ 열 제거로 Y축 원안 변수가 3개까지 줄었고, 표본 검사에서 세 변수 상호 상관이 −0.23 ~ −0.01로 거의 없었다. `thin_filer`와 `credit_score_residual`을 보강해 5개로 맞춘다. 그래도 PC1이 낮으면 `직업군` 원핫 추가를 검토할 것(코드북 확보 전제).

### 10.2 산출 절차

1. **방향 통일** — `(−)` 변수 부호 반전. 전 변수가 "높을수록 나쁨"이 되도록.
2. **분위수 정규화** — `rank(pct=True) × 100`. **train 기준 경계를 저장해 valid/test에 적용.** NaN은 중앙값(50) 대체 + `{var}__imputed` 플래그.
3. **가중치 — ★ 진단 분기**

   | 축별 PC1 설명분산비율 | 가중치 |
   |---|---|
   | ≥ 40% | PCA 제1주성분 로딩 절대값을 합=1로 정규화해 사용 |
   | < 40% | **균등가중** (현 기본값) |

4. **최종 스코어** = 가중합, 0~100.

PC1 수치와 분기 결과를 반드시 리포트에 기록할 것.

## 11. STEP 7 — 6유형 배정 (`segment.py`)

### 11.1 분류 순서 (엄수)

**(1) 특수 유형 사전 분리** — 결정적 규칙

```
T6  회생·파산 진행군    조건: 파산, 개인회생 신청 여부 == 1
T5  신용 무이력군       조건: Thin Filer == 1 AND 총대출건수 == 0 AND score_floor
```

- T6를 **먼저** 분리한 뒤 잔여에서 T5 분리 (중복 배정 방지)
- T5 분리 사유: 신용평점 150은 "취약해서"가 아니라 "정보가 없어서" 낮다. 분리하지 않으면 T3·T4가 오염된다
- T5가 100건 미만이면 `총대출건수 == 0` 조건을 완화한 대안 정의를 리포트에 병기

**(2) 주 분류** — 잔여에 2×2. 각 축 스코어의 **train 중앙값**을 임계값으로 사용(`config.py`에서 분위수 파라미터화, 기본 0.5).

| 유형 | 조건 | 명칭 |
|---|---|---|
| `T1` | 재무 안정 & 고용 안정 | 자산형성 준비군 |
| `T2` | 재무 취약 & 고용 안정 | 고정지출 압박군 |
| `T3` | 재무 안정 & 고용 불안 | **잠재 불안군** ⚠ 사각지대 |
| `T4` | 재무 취약 & 고용 불안 | **복합 위기군** ★ 최우선 |

### 11.2 주거 부담 수정자 (H flag)

```
H = (jeonse_income_multiple 상위 25%) OR (commute_mismatch == True)
```

표기 `T2-H`, `T3-H` 등. 운영 12구분, 발표 6유형.

### 11.3 크기 점검

- T6 제외하고 5% 미만 유형이 있으면 경고
- **T3 규모를 리포트 최상단에 강조 출력.** 5% 미만이면 다음 경고를 출력:

```
[WARNING] T3(잠재 불안군) 비중이 임계 이하입니다.
합성데이터가 고용 불안정과 재무 악화를 강하게 연동시켜 생성되었을 가능성이 있습니다.
'사각지대' 서사 대신 '고용 불안정 → 재무 악화 직결' 서사로 전환을 검토하십시오.
```

프로젝트 전략을 가르는 지점이므로 반드시 구현할 것.

### 11.4 GMM — ★ 진단 분기

| 최적 k의 실루엣 | 결정 |
|---|---|
| ≥ 0.25 | GMM 주도. 군집을 최종 라벨로 삼고 규칙은 사후 근사 |
| < 0.25 | **규칙 주도** (현 기본값). GMM은 검증 근거로만 |

공통 산출: PCA 3차원 → `k=2..8` GaussianMixture → BIC·실루엣 곡선 → 최적 k 군집과 규칙 라벨의 교차표·ARI·일치율

리포트 문장:
- 실루엣 ≥ 0.25 → "데이터가 자연 형성한 군집과 규칙 분류가 XX% 일치"
- 실루엣 < 0.25 → "군집 구조가 통계적으로 확인되지 않아(실루엣 X.XX) 도메인 규칙 기반으로 설계함"

> 후자도 발표 자산이다. "비지도 적용 가능성을 먼저 검증하고 불가 판정을 정량 근거와 함께 제시했다"는 서사가 된다.

## 12. STEP 8 — [학습 ③] 8문항 축소 분류기 (`reduced_model.py`) ★ 필수

**발상: 실제 사용자는 42개 금융변수를 들고 오지 않는다.**

### 12.1 입력 피처 8종

| # | 피처 | 원본 매핑 | 사용자 문진 |
|---|---|---|---|
| 1 | `age_band` | 연령대 | 나이 |
| 2 | `gender` | 성별 | 성별 |

### 12.2 학습

- 타깃: STEP 7의 6유형 라벨
- **주 모델: `DecisionTreeClassifier(max_depth=4~5)`**
- 비교군: `LogisticRegression` (multinomial) 1종
- 검증: Stratified 5-Fold + 홀드아웃 test
- 지표: macro F1, accuracy, 클래스별 precision/recall, confusion matrix
- 클래스 불균형에 `class_weight='balanced'`
- `predict_proba` 최대값(확신도) 분포 → 확신도 낮은 구간 비율 리포트 (추가 질문 트리거 근거)

> **순환논리가 아닌 이유**: 라벨은 42개 변수로 만들었고 입력은 8개다. 정보량이 줄어드는 압축이므로, "8문항으로 얼마나 복원되는가"를 재는 유효한 과제다.

## 13. STEP 9 — [학습 ④] 이상탐지 (`anomaly.py`)

## 16. 구현 시 함정 (반드시 준수)

1. **결측을 0으로 채우지 말 것.** `-99999999`는 결측이며, 결측 여부 자체가 취약주거 프록시일 수 있다.
2. **절대값 임계값 금지.** 모든 컷은 분위수 기준.
3. **train 외 데이터로 통계량을 계산하지 말 것.** 분위수·경계·중앙값·모델 전부 train 산출 → `fitted_params.json` 저장 → 나머지에 적용.
4. **직업군 코드에 의미를 부여하지 말 것.** 코드북 미확보. 원핫만 허용.
5. **신용평점 150은 하한 절단값이다.** 회귀에 그대로 투입 금지. `score_floor` 플래그 병용. **잔차 모델(STEP 5) 학습에서 제외할 것.**
6. **T5·T6를 주 분류보다 먼저 분리할 것.** 순서가 바뀌면 T3·T4가 오염된다.
7. **연령대 15·20 구간에 재학생이 혼입되어 있다.** 학력 컬럼이 없어 분리 불가. 별도 표기 + 25세 이상 민감도 분석 병기.
8. **p값 대신 효과크기로 해석할 것.** n=100,816에서는 사소한 차이도 유의하다.
9. **부스팅 계열 금지.** LightGBM·XGBoost·CatBoost·HistGradientBoosting 전부.
10. **PCA·GMM은 검증 후 적용.** §10.2·§11.4 분기 규칙을 반드시 구현하고 판정 근거 수치를 남길 것.
11. **개인 낙인 금지.** 유형 라벨은 개인 신용 판정이 아니라 **정책 아웃리치 우선순위**다. 리포트 서두에 명시.
12. **모든 난수 시드 고정.**

run.py

### 학습 지점 4곳 요약

| # | 단계 | 타깃 | 순환논리 | 우선순위 |
|---|---|---|---|---|
| ① | STEP 3 전세가 대체 | 전세거래가 (관측) | 없음 | 3순위 |
| ② | STEP 5 신용평점 잔차 | 신용평점 (관측) | 없음 | **2순위 ★** |
