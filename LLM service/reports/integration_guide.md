# DIVE AI 서버 외부 백엔드 연동 가이드

## 한눈에 보기

| 항목 | 값 |
|---|---|
| Base URL | `https://ai.beceleb.org` |
| 진단 | `POST /v1/diagnose` |
| 인증 | 없음 |
| Content-Type | `application/json` |
| 권장 timeout | 35초 |
| 계약 버전 | `1.2` |
| 입력값·KCB 필드 | `GET /v1/meta` |
| API 원본 계약 | `GET /openapi.json` |


```dotenv
DIVE_AI_BASE_URL=https://ai.beceleb.org
```


## 1. 상태 확인

```bash
curl -sS https://ai.beceleb.org/health/live
curl -sS https://ai.beceleb.org/health/ready
```

- `/health/live`: HTTP 200이면 연결 가능
- `/health/ready`: `capabilities`에서 `light_diagnosis`, `precise_classification`, `precise_rule_fallback` 확인

## 2. 호출 코드

Node.js 백엔드 예시:

```js
const AI_URL = process.env.DIVE_AI_BASE_URL ?? "https://ai.beceleb.org";

async function diagnose(payload) {
  const response = await fetch(`${AI_URL}/v1/diagnose`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
    signal: AbortSignal.timeout(35_000),
  });

  const result = await response.json();
  if (!response.ok) throw new Error(`DIVE AI ${response.status}: ${JSON.stringify(result)}`);
  return result;
}
```

공통 사용자 입력:

```js
const userInputs = {
  "성별": "여",
  "결혼여부": "미혼",
  "연소득": 30000000,
  "직업군": "재직자",
  "학력": "대학 졸업",
  "특화": [],
  "사는곳": "중구",
  "나이": 27,
};
```

`연소득`은 원 단위, `나이`는 필수 만 나이다. 허용 enum은 `/v1/meta`의 `user_input_options`를 사용한다.

## 3. 라이트 진단

```js
const result = await diagnose({
  mode: "light",
  user_inputs: userInputs,
});
```

- KCB 데이터와 LLM을 사용하지 않는다.
- `지원가능정책` 전체를 대분류별로 표시한다.
- 유형·점수는 `null`, `추천정책`은 빈 배열이다.

## 4. 정밀 진단

```js
const result = await diagnose({
  mode: "precise",
  user_inputs: userInputs,
  kcb_record: kcbRow,
});
```

`kcbRow`는 공식 KCB 한 행의 필수 43개 값을 각각 키로 가진 객체다. 필요한 필드명은 다음처럼 확인한다.

```bash
curl -sS https://ai.beceleb.org/v1/meta \
  | jq '.precise_input.required_kcb_columns'
```

필수 규칙:

- KCB 한 행을 문자열이나 배열이 아닌 JSON 객체로 보낸다.
- 43개 필드명은 `/v1/meta`와 공백까지 정확히 맞춘다.
- KCB 값의 원래 단위와 `-99999999`를 임의 변환하지 않는다.
- 연령 판정에는 KCB `연령대`가 아닌 `user_inputs.나이`가 우선한다.
- `추정가구원수`가 1이 아니어도 정밀 진단한다. 1이면 1인가구 상세 피드백이 추가된다.

## 5. 응답 처리

| 필드 | 처리 |
|---|---|
| `계약버전` | `1.2`인지 확인 |
| `진단상태` | `완료` 또는 `부분완료` |
| `분류상태` | `완료`일 때만 유형·점수 표시 |
| `유형`, `유형점수` | 정밀 진단 사용자 유형과 0~100점 분류 확신도 |
| `소비피드백` | 평균 비교와 1인가구 피드백 표시 |
| `지원가능정책` | 통과 정책 전체. `{대분류, 정책:[...]}` 묶음 |
| `추천정책` | 정밀 진단 상위 3~5개 |
| `추천방식` | `로컬LLM` 또는 `규칙기반대체` |

정책 항목에서 주로 사용할 값은 `plcyNo`, `plcyNm`, `설명`, `지원내용`, `신청URL`, `자격판정`, `판정근거`다.

```text
진단상태=완료
→ 전체 결과 표시

진단상태=부분완료 또는 분류상태=사용불가
→ 유형·점수만 숨기고 지원가능정책과 반환된 추천정책은 표시

추천방식=규칙기반대체
→ 정상 fallback이므로 추천정책 표시
```

## 6. 오류 처리

| HTTP | 처리 |
|---|---|
| `200` | 본문의 진단·분류·추천 상태 확인 |
| `422` | 필수 필드, 필드명, enum, 타입 확인 |
| `502` | AI 서버 연결 장애이므로 AI 서버 담당자에게 전달 |
| `503` | AI 서버 또는 PostgreSQL 준비 실패 |

네트워크 오류·502·503은 한 번만 재시도한다. HTTP 200이어도 `진단상태`, `분류상태`, `추천상태`, `추천방식`을 반드시 확인한다.

## 연동 완료 기준

1. 외부 백엔드에서 `/health/live` HTTP 200
2. 라이트 진단 `진단상태=완료` 및 `지원가능정책` 표시
3. 정밀 진단에서 KCB 43개 필드 전달 성공
4. 정밀 진단의 유형·점수·추천정책 또는 부분완료 fallback 처리

최종 계약은 `https://ai.beceleb.org/openapi.json`을 기준으로 한다.
