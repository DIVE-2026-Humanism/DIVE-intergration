핵심 원칙
---------
- apps = 사용자 대면 배포 / services = 독립 백엔드 / packages = 배포 안 되는 라이브러리
- contracts/ = 스키마 단일 진실. export 생산자(policy-pipeline)와 소비자(ai-server)가
  같은 파일을 봐서 스키마 드리프트 방지 (15 vs 175 같은 사고 예방)
- data/ = 공유 (kcb는 model·ai-server·pipeline 셋 다 사용)
- 폴리글랏이라 Nx/Turborepo 강제 안 함 → 최상위 Makefile + 언어별 기존 도구


현재 → 모노레포 매핑
--------------------
현재 위치                          →  모노레포 위치
DIVE2026/src/*.py                  →  packages/policy-pipeline/src/
DIVE2026/data/                     →  data/ (그대로, 루트 공유)
DIVE2026/docs/                     →  docs/ (그대로)
DIVE2026/meeting/                  →  meeting/ (그대로)
github/repository/DIVE-typepredict →  packages/model/
(팀) AI 서버 레포                   →  services/ai-server/
(팀) 프론트 레포                    →  apps/web/
(팀) 백엔드 레포                    →  apps/backend/
